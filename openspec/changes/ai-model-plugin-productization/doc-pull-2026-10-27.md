## 1. Tiptap Content AI / AI Toolkit

来源：https://tiptap.dev/docs/ai/ai-toolkit 、 https://tiptap.dev/docs/ai/ai-toolkit/client/install.md 、 https://tiptap.dev/docs/ai/basic/install.md 、 https://tiptap.dev/docs/ai/basic/custom-llms.md 、 https://tiptap.dev/docs/ai/ai-toolkit/client/agents/tools.md 、 https://tiptap.dev/docs/ai/ai-toolkit/client/agents/tools/ai-sdk.md 、 https://tiptap.dev/docs/llms.txt

**产品线现状（文档已重组，旧 `/docs/content-ai` 路径 404）**
- Basic AI Generation：即旧 Content AI 的 Ai 扩展，现为 `@tiptap-pro/extension-ai`（私有 registry，付费）。
- AI Toolkit：新主推，分 client（浏览器内直连 editor）与 server 两版，均为付费 add-on、私有 registry。
- 旧 AI Agent / AI Changes / AI Suggestion 三个扩展已整体移入 `/docs/ai/deprecated/`。

**安装**
- Basic AI：`.npmrc` 配 `@tiptap-pro:registry` + token 后 `npm install @tiptap-pro/extension-ai`；`Ai.configure({ token: '<JWT>', autocompletion: true })`。token 必须是签名 JWT（`aud: "AI"` + `AI:Generation` 权限），官方明确警告 token 不是 OpenAI API key；OpenAI key 配在 Tiptap Cloud AI 设置里。
- AI Toolkit client：`npm install @tiptap-pro/client-ai-toolkit`；代码 `extensions: [AiToolkit]` + `getAiToolkit(editor)`；要求 `@tiptap/*` ≥ 3.12.0。
- AI Toolkit 与 Vercel AI SDK 的桥：`npm install @tiptap-pro/client-ai-toolkit-ai-sdk`，导出 `toolDefinitions()`。
- 公开 npm 上的 `@tiptap/ai-toolkit`（0.4.1）是「连接 Server AI Toolkit 服务」的开源 SDK，与付费 client 包是两个东西。

**provider 配置**
- Basic AI：无 endpoint/requestOptions 配置项，改用 resolver 覆盖——`aiCompletionResolver` / `aiStreamResolver` / `aiImageResolver`，各自拿到 `{ editor, action, text, textOptions, extensionOptions, defaultResolver }`，自己写 `fetch` 调自家后端，或委托 `defaultResolver({...})` 走 Tiptap Cloud。流式 resolver 需返回 `ReadableStream<Uint8Array>` 且内容必须是 HTML；补全 resolver 返回 `Promise<string | null>`。官方警告：不要在前端直调 OpenAI，key 留后端。
- AI Toolkit：兼容「任何能产文本的模型」，官方列 Vercel AI SDK / LangChain / OpenAI SDK / Anthropic SDK / 自实现。

**tool calling**
- 内置工具：`tiptapRead`、`tiptapEdit`、`tiptapReadSelection`（默认启用），`getThreads`、`editThreads`（依赖 Comments 扩展，默认关）。工具定义按各家 AI 库格式分发（AI SDK / OpenAI / Anthropic / LangChain.js / Mastra / other）。
- 执行在 editor 端：`await agent.executeTool({ toolName: 'tiptapEdit', input: {...} })`——模型生成 tool call，宿主把它交给 editor。
- 服务端（AI SDK）：`toolDefinitions()` 传入 `ToolLoopAgent({ model, tools })` + `createAgentUIStreamResponse({ agent, uiMessages })`；可与自定义 `tool({...})` 合并。官方注明：应用用 Zod 3 时会出类型错误，需升 Zod 4 或 cast 成 AI SDK `ToolSet`。

**React 集成**
- client 包框架无关（直接操作 editor 实例），`@tiptap/react` 3.32.0 正常 `useEditor` 即可；未见专门的 `useAiToolkit` React hook 文档。
- AI SDK 集成形态：前端发 `UIMessage[]` 到服务端 POST，服务端跑 `ToolLoopAgent` 返回 agent UI stream。
- 官方 chatbot 指南页（client/agents/ai-agent-chatbot）多次抓取超时，未能取得内容——未在官方文档找到其具体 hook 用法。

**WebView（浏览器环境）兼容**
- client 包本身即设计为「in-browser、直接与 Editor 通信」，WebView 内可用。
- 模型调用官方示例全部放在服务端；WebView 内直连 provider 的官方支持说明：未在官方文档找到。

**版本号**：`@tiptap-pro/*` 各包当前版本号未公开（私有 registry，公共 npm 404）；仅能确认约束「`@tiptap/*` ≥ 3.12.0」。

## 2. Vercel AI SDK（ai@7）

来源：https://ai-sdk.dev/docs/introduction 、 https://ai-sdk.dev/docs/reference/ai-sdk-core/provider-registry 、 https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling 、 https://ai-sdk.dev/docs/reference/ai-sdk-core/ui-message 、 https://ai-sdk.dev/sitemap.xml

**provider registry**
- `import { createProviderRegistry } from 'ai'`；`createProviderRegistry({ openai, anthropic, ... })`。
- 取模型：`registry.languageModel('openai:gpt-4o')`，格式 `providerId:modelId`，`separator` 可配（如 `' > '`）。
- 检索方法族：`languageModel` / `embeddingModel` / `imageModel` / `transcriptionModel` / `speechModel` / `rerankingModel` / `videoModel` / `files(providerId)` / `skills(providerId)`；另有实验性 `decisionModel`。未知 provider 抛 `NoSuchProviderError`，能力缺失抛 `NoSuchModelError`。
- options：`languageModelMiddleware` / `imageModelMiddleware` 可包所有模型。provider 契约为 V4（`ProviderV4`、`VideoModelV4`）。
- 自定义 provider：`customProvider` 可做别名/预配置（https://ai-sdk.dev/docs/reference/ai-sdk-core/custom-provider ）。

**tool calling（当前 API 形状）**
- `import { tool, dynamicTool } from 'ai'`；`tool({ description, inputSchema, execute?, strict? })`，`inputSchema` 接受 Zod schema 或 `jsonSchema()` 包的 JSON Schema（v5 起由 `parameters` 更名，页面已无 `parameters`）。
- `execute` 可选：无 execute 即「转发到客户端/队列」的 client-side tool。
- 多步循环：`stopWhen: isStepCount(n) / hasToolCall(...) / isLoopFinished()`（替代旧 `maxSteps`）；`result.steps`、`onStepEnd`、`onToolExecutionStart/End` 可观测。
- 人审：`tool()` 上的 `needsApproval` 已 deprecated，改用 `generateText/streamText/ToolLoopAgent` 上的 `toolApproval`；审批态为 `'not-applicable' | 'approved' | 'denied' | 'user-approval'`；流程产出 `tool-approval-request` part，回 `tool-approval-response` 消息后重调。
- 动态 schema：`dynamicTool()`（MCP/运行期工具），输入 `unknown` 自行校验；`repairToolCall` 可修工具调用。

**UIMessage 结构**
```ts
interface UIMessage<METADATA = unknown, DATA_PARTS extends UIDataTypes = UIDataTypes,
                    TOOLS extends UITools = UITools> {
  id: string;
  role: 'system' | 'user' | 'assistant';
  metadata?: METADATA;
  parts: Array<UIMessagePart<DATA_PARTS, TOOLS>>;
}
```
- part 联合：`text`（含 `state?: 'streaming'|'done'`）、`reasoning`、`tool-${NAME}`、`data-${NAME}`、`file`、`source-url`、`source-document`、`step-start`、`custom`。
- tool part 状态机：`input-streaming` → `input-available` →（`approval-requested` / `approval-responded`）→ `output-available` | `output-error`（含 `errorText`）。
- 定位：UIMessage 是 UI 侧唯一事实源（可持久化），`ModelMessage` 是发给模型的形态；转换函数 `convertToModelMessages` 在其他页面（本页未展开）。

**WebView 兼容**
- UIMessage/`@ai-sdk/react` 侧是纯浏览器能力，WebView 可用；模型 provider 调用官方示例全部在服务端（Node POST handler）。WebView 内浏览器环境直连 provider 的官方兼容性说明：未在官方文档找到。

## 3. Tauri v2 secure storage / updater

来源：https://v2.tauri.app/plugin/ 、 https://v2.tauri.app/plugin/stronghold/ 、 https://v2.tauri.app/plugin/updater/ 、 crates.io search（--registry crates-io）

**官方 secure storage 现状：无官方 keyring / secure-storage 插件**
- 官方插件列表共 30 个（Autostart…Window State），其中不存在名为 keyring / secure-storage / secrets 的插件。
- 官方最接近的密钥存储方案是 **Stronghold** 插件：「Store secrets and keys using the IOTA Stronghold secret management engine」。
  - 安装：`npm run tauri add stronghold`（等价 `cargo add tauri-plugin-stronghold` + `npm install @tauri-apps/plugin-stronghold`，2.4.0）。
  - 全平台支持（Win/Linux/macOS/Android/iOS），要求 Rust ≥ 1.90。
  - 用法：`Stronghold.load(vaultPath, 'vault password')` → `client.getStore()` → `store.insert/get` → `stronghold.save()`；vault 文件如 `${appDataDir()}/vault.hold`。
  - 初始化必须提供「返回恰好 32 bytes」的密码 hash：内置 `Builder::with_argon2(&salt_path)`（salt 常放 `app_local_data_dir()/salt.txt`）或自定义函数。
  - 权限：`stronghold:default` 不含 destroy/remove 等危险命令。
  - 已知坑：dev profile 建议加 `[profile.dev.package.scrypt] opt-level = 3`。
- 社区方案（无官方背书，crates.io 实查）：`keyring` crate 4.2.0（跨平台系统 keyring，可在 Rust command 层直接用，无需插件）；`tauri-plugin-keyring` 0.1.0（keyring crate 的薄封装）；`tauri-plugin-keyring-store` 0.2.0。三者均无 npm 包（npm 实查 404），只能走 Rust 侧。

**updater 插件（官方，2.14.0）**
- 安装：`npm run tauri add updater`；Rust 侧 `#[cfg(desktop)]` 下 `app.handle().plugin(tauri_plugin_updater::Builder::new().build())`。
- 流程：`const update = await check()` → `update.downloadAndInstall(event => ...)`（Started/Progress/Finished）→ `relaunch()`（process 插件）；可延迟到用户手动重启。
- 端点：`plugins.updater.endpoints` 数组，支持静态 JSON（`version` + `platforms[target].{url,signature}`）或动态 server（无更新回 204）；URL 变量 `{{current_version}}/{{target}}/{{arch}}`；生产模式强制 TLS。
- 签名强制不可关闭：`npm run tauri signer generate` → pubkey（必须是 key 内容，不能是路径）写入 `tauri.conf.json`；构建注入 `TAURI_SIGNING_PRIVATE_KEY`（.env 不生效）；`bundle.createUpdaterArtifacts: true` 产出 `.sig`。
- Windows `installMode` 默认 `passive`；安装步执行时应用会被自动退出，需 `on_before_exit` 清理。

**与本仓库衔接**：`src-tauri/Cargo.toml` 锁 `tauri = "2"`（macos-private-api + tray-icon + protocol-asset），`package.json` 锁 `@tauri-apps/api`/`cli` `^2`。

## 4. MCP（Model Context Protocol）

来源：https://modelcontextprotocol.io/specification/versioning 、 https://modelcontextprotocol.io/specification/2025-11-25 、 https://modelcontextprotocol.io/specification/2025-11-25/server/tools 、 https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization

**版本现状**
- 官方 versioning 页明确：「The current protocol version is **2025-11-25**」。第三方媒体报道过 2026-07-28 修订，但官方版本页未列出该版本——以官方为准。
- TS SDK `@modelcontextprotocol/sdk` 1.32.2。

**tools schema 要点（2025-11-25）**
- 能力声明：server 支持工具必须声明 `tools` capability（`listChanged` 表示会发列表变更通知）。
- 消息：`tools/list`（分页）、`tools/call`、`notifications/tools/list_changed`。
- Tool 定义字段：`name`（1-128 字符，仅 `[A-Za-z0-9_.-]`，SHOULD 大小写敏感、server 内唯一）、`title?`、`description`、`icons?`、`inputSchema`（JSON Schema，缺省按 2020-12；无参工具推荐 `{"type":"object","additionalProperties":false}`；必须为合法 object 不能是 null）、`outputSchema?`、`annotations?`、`execution.taskSupport?`（`forbidden` 默认 / `optional` / `required`）。
- 结果：`content`（text / image / audio / resource link / embedded resource）+ `structuredContent`（JSON object）；声明了 `outputSchema` 则 server MUST 遵守、client SHOULD 校验；向后兼容 SHOULD 同时在 TextContent 里返回序列化 JSON。
- 错误双轨：protocol error（JSON-RPC error，结构问题）vs tool execution error（结果内 `isError: true`，模型可自纠）；client SHOULD 把 execution error 喂回模型。
- 安全要求：server MUST 校验输入/访问控制/限流/输出消毒；client SHOULD 对敏感操作要用户确认、展示 tool 输入、校验结果、实现超时、审计日志。

**authorization 现状（2025-11-25）**
- 基座：OAuth 2.1 draft（draft-ietf-oauth-v2-1-13）+ RFC8414 + RFC7591 + RFC9728 + Client ID Metadata Documents draft-00。授权对 MCP 实现是 OPTIONAL；HTTP 传输 SHOULD 遵循，**stdio 传输 SHOULD NOT 用这套**（从环境取凭证）。
- 发现：MCP server MUST 实现 RFC9728 Protected Resource Metadata（401 的 `WWW-Authenticate: resource_metadata` 或 well-known URI），metadata 必含 `authorization_servers`；client MUST 支持两种发现途径且优先 `WWW-Authenticate`。issuer 带路径时 client MUST 按序试 3 个 well-known 端点。
- client 注册三途径 + 优先级：pre-registered → Client ID Metadata Documents（AS 在 metadata 标 `client_id_metadata_document_supported`）→ Dynamic Client Registration（RFC7591）→ 提示用户手输。
- MUST 项：授权与 token 请求都带 RFC8707 `resource` 参数（canonical URI）；PKCE 且 `S256`，metadata 无 `code_challenge_methods_supported` 必须拒绝继续；token 只走 `Authorization` 头、禁 query string、每个请求都带；server MUST 校验 token audience（防 token passthrough / confused deputy）。
- 运行期权限不足：403 + `WWW-Authenticate: error="insufficient_scope", scope=...`，client SHOULD 走 step-up 授权并限制重试次数。
- 授权扩展（extension）机制：可选、可组合、独立版本化（MCP Authorization Extensions repo）。

**WebView 注意**：授权规范只覆盖 HTTP 传输；浏览器/WebView 作为 MCP client 走 HTTP + OAuth 是规范主场景，stdio 不适用。

## 5. Tiptap AI 降级路径（失败/超时的官方推荐处理）

来源：https://tiptap.dev/docs/ai/basic/text-generation/manage-responses.md 、 https://tiptap.dev/docs/ai/ai-toolkit/client/api-reference/edit-the-document.md 、 https://tiptap.dev/docs/ai/ai-toolkit/client/api-reference/review-options

**Basic AI Generation（@tiptap-pro/extension-ai）**
- 错误暴露靠 storage 状态机：`editor.storage.ai.response.state: 'loading' | 'error' | 'idle'`，失败时 `response.error` 持有错误对象；该页无 `onError` 回调。
- 恢复/重试命令：`aiReject({ type: 'reset' })` 回到 idle 并还原 `initialContent`（AI 插入前 Slice）；`aiReject({ type: 'pause' })` 保留 storage（保留现场排查）；`aiRegenerate` 同参重试；`aiAccept` 落定。多步链回退需 `regenerate: true` 重跑。
- 预览不落稿：TextOption `insert: false`（可配 `stream: true`），配 `tryParseToTiptapHTML()` 做 HTML 预览。
- provider 级 fallback / 超时配置：未在官方文档找到。

**AI Toolkit client**
- 流式方法（`streamText` / `streamHtml` 等）提供：
  - `onError?: (event: { error, chunk, content, range }) => void`——流中错误回调；
  - `checkChunkForError?: (status: { chunk, content, range }) => boolean`——返回 true 即停流并抛 `StreamingChunkCheckFailedError`；
  - `onChunkInserted` 逐块回调。
- 写入审查是官方主推路径：五个编辑方法均收 `reviewOptions?: ReviewOptions`（「Control preview/review behavior」），AI 修改先走 review UI 再 accept/reject——即「AI 写入必须经 preview/confirm」在官方层面对应 reviewOptions 机制。
- timeout / retry / 自动 fallback provider 参数：未在官方文档找到。

**结论性事实**
- 官方没有「AI 失败自动降级到另一个编辑器」的文档；最接近的官方机制 = Basic AI 的 `error` 状态 + `aiReject(reset)`（内容回滚）与 AI Toolkit 的 `onError` + `reviewOptions`（写入前确认）。提案里「Tiptap 失败降级到紧凑编辑」需宿主自行基于上述状态机实现。
